# paper-start — 점검, 설정, 길 안내

이 스킬은 세 가지만 한다. 환경을 점검하고, 설정을 한 번 잡아 주고, 지금 할 일에 맞는 스킬을 알려 준다. 논문 작업 자체는 하지 않는다.

도우미 스크립트는 하나다. 아래에서 `PTK`는 이 명령을 뜻한다.

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/ptk.py"
```

`${CLAUDE_SKILL_DIR}`가 글자 그대로 보이면 이 SKILL.md가 들어 있는 폴더 경로로 바꿔 쓴다. 윈도우에서 `python3`가 없으면 `python`이나 `py -3`을 쓴다.

## 언제 무엇을 하나

| 사용자 상황 | 할 일 |
|---|---|
| 방금 설치했다, 처음 쓴다, 설정 파일이 없다 | 1. 점검 → 2. 처음 설정 → 3. 길 안내 |
| "점검해줘", "왜 안 되지" | 1. 점검만 |
| "뭐부터 하지", "어떤 스킬 써야 해" | 3. 길 안내만 |

## 1. 점검

`PTK doctor`를 실행하고 결과를 그대로 요약한다. 규칙은 다음과 같다.

- ✅ 항목은 개수만 말한다. 하나씩 읽어 주지 않는다.
- ➖ 항목은 "선택 사항"이다. 고장이 아니다. 그 항목을 쓰는 스킬과 해결 방법을 표로 보여 주고, 사용자가 지금 필요한 것만 고르게 한다.
- 사용자가 고른 항목만 설치를 돕는다. API 키는 사용자가 직접 발급받아 입력하게 한다. 키를 대화에 붙여 넣으라고 요청하지 않는다.
- 프로그램 설치(Zotero, Node.js, Pandoc 등)는 실행 전에 무엇을 설치하는지 말하고 동의를 받는다.

## 2. 처음 설정

설정 파일은 `~/.config/paper-toolkit/config.json`이다. `PTK config show`로 지금 값을 본다. 비어 있으면 아래 세 가지를 **한 번에** 묻는다. 답하지 않은 항목은 괄호 안 기본값을 제안하고 동의를 받는다.

1. 논문 작업 폴더가 어디인가 (기본 제안: `~/Documents/논문`)
2. 읽은 논문 노트를 쌓을 위키 폴더를 어디에 둘까 (기본 제안: 논문 작업 폴더 안의 `논문_wiki`)
3. 전공 분야가 무엇인가 (예: 사회복지학, 교육학. 투고 학술지를 찾을 때 쓴다)

옵시디언 볼트나 따로 쓰는 메모 폴더가 있으면 함께 알려 달라고 한다. 없으면 넘어간다.

답을 받으면 저장한다.

```bash
PTK config set paper_dir "<논문 작업 폴더>"
PTK wiki-init "<위키 폴더>"          # 폴더 뼈대를 만들고 wiki_dir에 저장한다
PTK config set field "<분야>"
PTK config set notes_dirs "<폴더1>,<폴더2>"   # 있을 때만. 쉼표로 구분
PTK config set zotero_dir "<경로>"            # Zotero 데이터 폴더가 ~/Zotero가 아닐 때만
```

폴더가 없으면 만들기 전에 경로를 다시 확인받는다. 저장한 뒤 `PTK config show` 결과를 보여 준다.

## 3. 길 안내

사용자에게 지금 상황을 한 문장으로 말해 달라고 한다. 이미 말했으면 묻지 않는다. 아래 표에서 **하나**를 골라 추천하고, 바로 붙여 넣을 수 있는 입력 예시를 함께 준다. 스킬 목록 전체를 나열하지 않는다.

| 지금 상황 | 추천 스킬 | 입력 예시 |
|---|---|---|
| 주제가 안 잡힌다, 글이 안 써진다 | `paper-writing-order` | `/paper-writing-order 주제를 못 정하겠어요. 관심 분야는 ○○입니다.` |
| 어떤 검색 도구를 쓸지 모르겠다 | `ref-toolkit` | `/ref-toolkit 국내 문헌 위주로 빠르게 훑고 싶어.` |
| 국내 학위논문·학술지 논문을 찾는다 | `keris-academic-search` | `RISS에서 ○○ 관련 최근 5년 박사논문 찾아서 표로 만들어줘.` |
| 내 Zotero 서재를 조회·점검한다 | `zotero` | `/zotero 인용 가능한 문헌이 몇 편인지, 빠진 서지가 뭔지 알려줘.` |
| 논문 한 편을 제대로 공부한다 | `paper-study` | `/paper-study inbox에 넣은 논문 같이 공부하자.` |
| 전에 정리한 게 있는지 본다 | `wiki-recall` | `/wiki-recall ○○ 관련해서 내가 정리해 둔 게 있나?` |
| 법령·판례를 인용한다 | `korean-law-search` | `○○법 제○조 원문 보여주고, 내 원고의 법 인용이 맞는지 검증해줘.` |
| AI 도움으로 쓴 글이 기계 같다 | `humanize` | `/humanize 2장-초안.md` |
| 내가 쓴 글을 다듬는다 | `toego-korean` | `/toego-korean 서론.md` |
| 맞춤법, 글자수 | `korean-spell-check`, `korean-character-count` | `/korean-spell-check 초록.md — 바뀐 곳만` |
| 어떤 보고 지침을 따라야 하나 | `reporting-guideline-router` | `/reporting-guideline-router 설문과 면접을 함께 쓴 혼합연구야.` |
| 투고 전에 약점을 찾는다 | `paper-critical-review` | `/paper-critical-review full-draft.md` |
| 어느 학술지에 낼지 고른다 | `kci-journal-finder` | `○○학 등재지 중 대학원생 게재료 감면 있는 곳 추려줘.` |
| 한글(HWP·HWPX) 양식을 읽거나 만든다 | `read-hwp`, `hwpx-mouseco` | `template.hwpx 구조 읽어줘.` |
| 자료 묶음으로 요약·오디오를 만든다 | `notebooklm` | `/notebooklm 이 PDF 5개로 노트북 만들어줘.` |
| 한 주 연구를 돌아본다 | `weekly-review` | `/weekly-review` |

개요 작성, 초안 집필, 인용 검증, 심사평 대응은 ARS 플러그인(`/ars-outline`, `/ars-full`, `/ars-citation-check`, `/ars-revision-coach`)이 맡는다. 점검 결과에 ARS가 ➖로 나오면 설치 명령을 알려 준다.

상황별 전체 흐름은 저장소의 `MANUAL.md` 2부에 시나리오 10개로 정리돼 있다.

## 지킬 것

- 추천은 하나만 한다. 사용자가 더 물으면 그때 다음 것을 알려 준다.
- 설치되지 않은 스킬을 추천하지 않는다. 확신이 없으면 `PTK doctor`의 "스킬 폴더" 줄에서 개수를 확인한다.
- 인용, 통계 수치, 법 조문은 어느 스킬을 쓰든 원문 확인이 원칙이라고 한 번 알려 준다.
