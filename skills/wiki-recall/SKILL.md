# wiki-recall — 쌓아 둔 것부터 꺼내기

## 왜 필요한가

`paper-study`로 논문 노트를 쌓아도, 막상 장(章)을 쓰기 시작할 때는 그 노트를 열어 보지 않고 백지에서 시작하기 쉽다. 이 스킬은 그 사이를 잇는다. 쓰기 전에 가진 것부터 꺼낸다.

## 어디를 찾나

설정 파일 `~/.config/paper-toolkit/config.json`의 두 값을 쓴다.

- `wiki_dir`: 논문 위키 폴더 (`paper-study`가 노트를 쌓는 곳)
- `notes_dirs`: 그 밖의 메모 폴더 목록 (옵시디언 볼트, 연구일지 폴더 등). 없어도 된다.

둘 다 비어 있으면 검색하지 않는다. 사용자에게 노트 폴더가 어디인지 묻고, `/paper-start`로 설정하도록 안내한다.

## 절차

### 1. 검색어를 만든다

사용자의 요청에서 **짧은 명사 2~5개**를 뽑는다. 주제어, 이론 이름, 대상 집단, 저자 이름이 좋다. 복합어는 쪼갠다. `사회복지정책`으로 못 찾으면 `사회복지`와 `정책`으로 다시 찾는다. 영어 논문 노트가 섞여 있으면 영어 낱말도 함께 넣는다.

### 2. 찾는다

```bash
python3 "${CLAUDE_SKILL_DIR}/../paper-start/scripts/ptk.py" recall 다문화교육 인권교육 Banks
```

`${CLAUDE_SKILL_DIR}`가 글자 그대로 보이면 이 SKILL.md가 들어 있는 폴더 경로로 바꿔 쓴다. 윈도우에서 `python3`가 없으면 `python`을 쓴다.

검색어를 많이 담은 노트부터 제목, 경로, 걸린 줄이 나온다. 결과가 없으면 더 짧은 낱말로 한 번 더 찾는다. 스크립트를 쓸 수 없으면 Grep 도구로 같은 폴더를 직접 찾는다.

### 3. 실제 파일을 읽는다

검색 결과는 후보일 뿐이다. 관련 있어 보이는 노트는 Read로 열어 내용을 확인한다. 우선순위는 다음과 같다.

1. `papers/`의 논문 노트. 특히 "파인만 재설명"과 "내 연구 적용 아이디어"는 사용자가 직접 쓴 부분이라 가장 값지다.
2. `concepts/`의 개념 노트. 어느 논문들이 이 개념에 걸려 있는지 보여 준다.
3. 그 밖의 메모와 연구일지.

### 4. 보고한다

없으면 없다고 분명히 말한다. 그것도 정보다.

```
## 가진 것

### 논문 노트
- [[2021-banks-multicultural]]: 한 줄 요약. 내가 남긴 적용 아이디어: ...

### 개념 노트
- [[비판적-다문화주의]]: 연결된 논문 3편

### 그 밖의 메모
- 연구일지/2026-09-12.md: 무엇에 대한 기록인지

## 빈 곳
- (찾았으나 아무것도 없는 영역. 이번에 새로 읽어야 할 부분)
```

### 5. 다음 단계를 잇는다

| 하려는 일 | 이어갈 스킬 |
|---|---|
| 논문 기획, 뼈대 세우기 | `paper-writing-order` |
| 빈 곳의 문헌 찾기 | `ref-toolkit`, `keris-academic-search` |
| 빈 곳의 논문 공부하기 | `paper-study` |
| 개요·초안 쓰기 | ARS 플러그인의 `/ars-outline`, `/ars-full` |

## 되돌려 쌓기

찾기만 하고 끝내면 검색기와 다를 것이 없다. 이번 작업에서 새로 정리한 내용 가운데 다시 쓸 만한 것은 위키에 되돌려 둔다.

- 여러 노트를 묶어 만든 정리는 `wiki_dir` 아래 `syntheses/YYYY-MM-DD-주제.md`로 저장할지 사용자에게 묻는다.
- 빈 곳으로 확인된 주제는 `index.md`의 "읽을 것" 목록에 추가할지 묻는다.

## 하지 말 것

- 없는데 있는 척하지 않는다. 결과가 비면 "쌓아 둔 것이 없으니 새로 시작해야 한다"고 말한다.
- 노트를 통째로 베껴 붙이지 않는다. 요약하고 경로를 준다.
- 글을 대신 쓰지 않는다. 이 스킬은 재료만 꺼낸다.
