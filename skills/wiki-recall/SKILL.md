# wiki-recall — 축적분 먼저 꺼내기

## 왜 이 스킬이 있나

설교·논문·강의·저술 스킬이 잘 만들어져 있지만, **그 스킬들이 사용자의 축적된 지식을 모른 채 매번 백지에서 시작한다.** 정작 볼트에는 Raw Sources 501건, Wiki 69페이지, 모선 노트 6,900여 건이 쌓여 있다.

이 스킬은 그 사이를 잇는다. **작업 스킬을 부르기 전에 재료를 꺼내 온다.**

---

## 대상 저장소 두 곳

| 저장소 | 인덱스 | 내용 |
|--------|--------|------|
| **LLM 위키** | `~/DEV/my-llm-wiki/.qmd/index.sqlite` | 정제된 Wiki 페이지 · 원본 자료 · 과거 질의 결과 (571건, 의미검색 가능) |
| **모선 볼트** | `~/DEV/my-llm-wiki/.qmd/mothership.sqlite` | 옵시디언 개인 볼트 — 과거 설교·강의·클리핑 (6,921건). **키워드검색을 쓸 것** |

> [!warning] `--index` 를 반드시 붙인다
> 빠뜨리면 현재 폴더의 없는 인덱스를 보고 `문서 0건` 으로 나온다.

---

## Process

### 1. 검색어를 만든다

사용자의 요청에서 검색어를 뽑되 **짧은 명사 단위로 2~5개**를 만든다.

- 성경 본문이면: 책이름 + 장 (`로마서 8`), 핵심 신학 개념 (`칭의`, `성화`)
- 논문이면: 주제어, 이론명, 대상 집단
- 강의면: 과목명, 단원 개념

> [!important] 저장소마다 쓰는 명령이 다르다 — 실측 결과
> - **LLM 위키 → `search`(의미검색)**: 자연어 문장으로 물어도 된다. 본문에 없는 표현으로도 찾는다.
>   예: `앞이 안 보이는 사람을 돕는 기기` → MOC-시각장애 AI안경 연구
> - **모선 볼트 → `fts`(키워드)**: 모선은 정제되지 않은 원본 더미라 **의미검색이 불안정하다.**
>   2026-07-30 실측 — 직접어 `시각장애인 보조기기` 로도 엉뚱한 문서를 반환. 반면 `fts "시각장애"` 는 정확.
>   대신 `fts` 는 **복합어를 붙이면 못 찾는다**: `사회복지정책` ✗ → `사회복지` ✓
>
> 이 차이가 이 위키의 존재 이유다 — **정제된 지식은 의미로 찾히고, 원본 더미는 단어로만 찾힌다.**

### 2. 두 저장소를 모두 검색한다

```bash
W="~/DEV/my-llm-wiki/.qmd/index.sqlite"
M="~/DEV/my-llm-wiki/.qmd/mothership.sqlite"

# LLM 위키 — 의미검색. 자연어 문장 그대로 물어도 된다
qmd --index "$W" search "앞이 안 보이는 사람을 돕는 기기" -n 5

# 모선 볼트 — 키워드검색. 짧은 명사로 끊어서
qmd --index "$M" fts "시각장애" -n 5
qmd --index "$M" fts "로마서" -n 5

# 고유명사·성경 장절·인명은 위키에서도 fts 가 더 정확하다
qmd --index "$W" fts "요한복음 3장" -n 5
```

검색어마다 반복한다. 결과가 없으면 더 짧은 단어로 다시 시도한다.

### 3. 실제 파일을 읽는다

검색 결과는 경로와 점수만 준다. **관련 있어 보이는 것은 Read 로 실제 내용을 확인한다.** 특히:

- `20. Wiki/` 하위 페이지 — 이미 정제된 지식. **최우선으로 읽는다**
- `30. Queries/` — 과거에 내가 합성해 둔 답변. 있으면 금맥이다
- `10. Raw Sources/` — 원문이 필요할 때만
- 모선 `1004. sermon/`, `002. Folder/강의/` — 과거 설교·강의 노트

### 4. 보고한다

다음 형식으로 정리한다. **없으면 없다고 분명히 말한다** — 그것도 정보다.

```
## 축적분

### 정제된 위키 페이지
- [[페이지명]] — 한 줄 요약 (confidence: high/medium/low)

### 과거에 내가 정리한 답변
- 30. Queries/... — 무엇에 대한 답이었는지

### 모선 볼트의 과거 작업
- 1004. sermon/... — 과거 이 본문으로 설교한 기록

### 원본 자료
- 10. Raw Sources/... — 관련 원문

## 빈 곳
- (검색했으나 아무것도 없는 영역 — 이번에 새로 만들어야 할 부분)
```

### 5. 다음 단계를 연결한다

재료를 넘기며 **어느 작업 스킬로 이어갈지** 제안한다.

| 작업 | 이어갈 스킬 |
|------|------------|
| 대지설교 구조 | `sermon-expository-daeji` |
| 본문 다각도 분석 | `sermon-text-analysis-multimethod` |
| 주석 검색 | `logos-bible-research` MCP |
| 설교문 문체 | `sermon-emotive-writing-coach` |
| 논문 기획 | `paper-writing-order` |
| 강의 슬라이드 | `pptx-design-styles` · `my-ppt` |

## 마무리 규칙 — 되돌려 쌓기

> [!important] 이게 없으면 이 시스템은 그냥 검색기다
> 조회로 끝내지 말고, **작업 결과 중 재사용할 가치가 있는 것은 위키에 되돌린다.**

- 합성한 답변 → `30. Queries/YYYY-MM-DD-Q-{질문}.md`
- 새로 정리한 개념 → 볼트에서 `/ingest` 로 Wiki 페이지 생성
- 빈 곳으로 확인된 영역 → 다음에 자료를 만나면 `/ingest` 대상

볼트 커맨드(`/query`, `/ingest`)는 **클로드 코드를 볼트 폴더에서 실행할 때** 쓸 수 있다:

```bash
cd ~/DEV/my-llm-wiki
```

밖에서 작업했다면 나중에 볼트에서 `/reindex` 를 한 번 돌린다 — 자동 색인 훅은 볼트를 프로젝트 폴더로 열었을 때만 작동한다.

---

## 하지 말 것

- **없는데 있는 척하지 않는다.** 검색 결과가 비면 "축적분 없음, 새로 시작해야 함"이라고 분명히 말한다.
- **원본 자료를 그대로 베껴 붙이지 않는다.** 요약하고 경로를 준다. 사용자가 필요하면 직접 연다.
- **작업을 대신 하지 않는다.** 이 스킬은 재료만 꺼낸다. 설교문·논문·강의안 작성은 전용 스킬 몫이다.
