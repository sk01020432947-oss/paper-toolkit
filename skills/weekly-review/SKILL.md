# weekly-review — 기록에 근거한 주간 연구 회고

## 원칙

**실제로 확인한 파일과 날짜만 근거로 삼는다.** "아마 이것도 하셨을 것"은 쓰지 않는다. 기록이 없는 영역은 "기록 없음"이라고 적는다. 빈칸이 보이는 것이 회고의 재료다.

## 1. 기간을 정한다

기본은 최근 7일이다. 사용자가 월간이라고 하면 30일로 잡는다. 기간을 먼저 말하고 시작한다.

## 2. 근거를 모은다

```bash
python3 "${CLAUDE_SKILL_DIR}/../paper-start/scripts/ptk.py" week --days 7
```

`${CLAUDE_SKILL_DIR}`가 글자 그대로 보이면 이 SKILL.md가 들어 있는 폴더 경로로 바꿔 쓴다. 윈도우에서 `python3`가 없으면 `python`을 쓴다.

이 명령은 설정 파일(`~/.config/paper-toolkit/config.json`)의 `paper_dir`, `wiki_dir`, `notes_dirs`에서 기간 안에 바뀐 연구 파일(md, docx, hwpx, pdf, bib, csv 등)과 Zotero에 새로 담은 문헌을 보여 준다. 설정이 비어 있으면 `/paper-start`로 먼저 설정하게 안내한다.

여기에 다음을 더 본다.

- **지난 회고**: `paper_dir` 아래 `회고/` 폴더의 가장 최근 파일. "다음 주 우선순위"와 "다시 미룸"을 읽어 이번 주에 처리됐는지 대조한다.
- **연구일지**: `paper_dir`에 `연구일지.md`가 있으면 기간 안의 항목을 읽는다.
- **git 이력**: `paper_dir`가 git 저장소면 `git log --since="7 days ago" --oneline`을 본다.
- **바뀐 파일의 내용**: 목록만으로 무슨 일인지 알 수 없는 파일은 열어서 확인한다. 파일 이름만 보고 짐작하지 않는다.

## 3. 연구 단계로 나눈다

| 단계 | 신호가 되는 것 |
|---|---|
| 기획 | 주제·연구 질문·목차 파일의 변경 |
| 수집 | Zotero 새 문헌, 검색 결과 표, `inbox/`의 새 PDF |
| 학습 | 위키 `papers/`·`concepts/`의 새 노트, `status: reading` 노트의 진행 |
| 집필 | 장(章) 초안 파일의 변경. 분량 변화가 보이면 적는다 |
| 분석 | 데이터, 분석 결과, 표·그림 파일의 변경 |
| 퇴고·점검 | 수정본, 심사 메모, 체크리스트 |
| 투고·심사 대응 | 투고본, 심사평, 답변서 |

## 4. 회고를 쓴다

```markdown
# 주간 연구 회고 — YYYY-MM-DD ~ YYYY-MM-DD

## 이번 주의 한 가지
(가장 의미 있었던 일 하나. 분량이 아니라 무게로 고른다)

## 단계별 진척

| 단계 | 움직임 | 근거 |
|---|---|---|
| 수집 | Zotero 문헌 6건 추가 | Zotero 추가 기록 10-08, 10-10 |
| 집필 | 2장 초안 2.1~2.2절 | 2장-초안.md (10-11 수정) |
| 분석 | 기록 없음 | |

## 지난주에 미룬 일
- [x] 처리함: ...
- [ ] 다시 미룸: ... (몇 주째인지 적는다)

## 관찰
(기록에서 드러난 흐름. 예: 문헌은 늘었는데 노트는 3주째 그대로다)

## 다음 주 우선순위
1. (가장 오래 미룬 일)
2. (기록이 없는 단계 가운데 지금 필요한 것)
3. ...
```

움직임이 없던 단계는 지우지 말고 "기록 없음"으로 남긴다.

## 5. 저장한다

`paper_dir` 아래 `회고/YYYY-MM-DD-주간회고.md`로 저장한다. 폴더가 없으면 만든다. 월간 회고는 원자료를 다시 훑지 말고 이미 써 둔 주간 회고들을 읽어서 만든다.

## 하지 말 것

- 기억으로 채우지 않는다. 확인되지 않은 일은 없었던 일로 다룬다.
- 모든 단계를 억지로 채우지 않는다.
- 칭찬으로 때우지 않는다. 미룬 일과 3주째 멈춘 단계를 그대로 적는다.
- 저장을 건너뛰지 않는다. 저장하지 않으면 다음 회고가 다시 백지에서 시작한다.

## 정기 실행

이 스킬은 부를 때만 실행된다. 매주 자동으로 돌리고 싶으면 `/schedule`로 등록할 수 있지만, 실행할 때마다 토큰이 든다는 점을 사용자에게 먼저 알린다.
