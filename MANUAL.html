논문 스킬 매뉴얼집 (paper-toolkit v1.3)

논문을 기획하고, 문헌을 모으고, 읽고, 쓰고, 다듬고, 심사에 대비하고, 투고처를 고르고, 한글(HWPX)로 제출하기까지 쓰는 Claude Code 스킬 21종의 사용 설명서입니다.

  • 1부 시작하기: 설치하고 첫 대화를 나누는 법
  • 2부 상황별 따라 하기: 연구 단계마다 무엇을 입력하면 무엇이 돌아오는지 보여 주는 시나리오 10개
  • 3부 스킬 사전: 스킬 21종 각각의 용도, 부르는 법, 결과물, 주의점
  • 4부 자주 묻는 질문

입력 예시는 그대로 복사해 써도 되고 자기 말로 바꿔도 됩니다. Claude는 명령어보다 말을 알아듣습니다.

1부. 시작하기

1-1. 설치

① 붙여넣기로 설치 (권장, 맥·윈도우 공통). 아래 글을 통째로 복사해 Claude Code 대화창에 붙여 넣습니다. Claude가 설치하고 점검 결과까지 보여 줍니다. 명령 실행을 허용할지 물으면 허용해 주세요.

논문 도구 묶음 paper-toolkit을 내 Claude Code에 설치해 줘.

저장소: https://github.com/sk01020432947-oss/paper-toolkit

1. 터미널에서 아래 두 명령을 차례로 실행해.
   claude plugin marketplace add sk01020432947-oss/paper-toolkit
   claude plugin install paper-toolkit@paper-toolkit
   이미 설치돼 있다고 나오면 대신 이 두 명령으로 최신판으로 올려 줘.
   claude plugin marketplace update paper-toolkit
   claude plugin update paper-toolkit@paper-toolkit
2. 1번이 실패하면 저장소를 내 홈 폴더의 paper-toolkit 폴더로 git clone 한 다음,
   그 폴더에서 python3 skills/paper-start/scripts/ptk.py install 을 실행해.
   (윈도우에서 python3가 없으면 python)
3. 설치가 끝나면 설치된 폴더에서 ptk.py 파일을 찾아
   python3 <경로>/ptk.py doctor 를 실행하고 결과를 표로 정리해 줘.
4. 내 기존 스킬과 설정은 지우거나 덮어쓰지 마.
   프로그램 설치나 API 키가 필요한 항목은 설치하지 말고 목록만 알려 줘.
5. 마지막에 무엇이 설치됐는지 요약하고,
   "Claude Code를 다시 시작한 뒤 /paper-start 를 입력하세요"라고 안내해 줘.

ZIP 파일로 받았다면 INSTALL-PROMPT.md의 ②번 글을 씁니다.

② 직접 입력해서 설치. Claude Code 대화창에 두 줄을 차례로 입력합니다.

/plugin marketplace add sk01020432947-oss/paper-toolkit
/plugin install paper-toolkit@paper-toolkit

③ 복사해서 설치. 플러그인 기능을 쓰기 어려울 때 씁니다. 저장소를 받은 뒤 그 폴더에서 실행합니다.

git clone https://github.com/sk01020432947-oss/paper-toolkit
python3 paper-toolkit/skills/paper-start/scripts/ptk.py install

스킬은 ~/.claude/skills/에, 에이전트는 ~/.claude/agents/에 복사됩니다. 같은 이름이 이미 있으면 건너뜁니다. --force를 붙이면 기존 것을 ~/.claude/backup-paper-toolkit-<시각>/으로 옮기고 덮어씁니다. 윈도우에서는 python3 대신 python을 씁니다.

어느 방법이든 설치 뒤에는 Claude Code를 완전히 종료했다가 다시 시작해야 스킬이 보입니다.

윈도우에서 Zotero·Obsidian·Pandoc 같은 프로그램까지 한 번에 설치하고 싶으면 Claude에게 "paper-toolkit 저장소의 install.ps1로 프로그램도 설치해줘. 무엇을 설치하는지 먼저 보여줘"라고 하세요. 설치 목록은 AGENT-INSTALL.md에 있습니다.

낱말 풀이. 플러그인은 스킬 여러 개를 한 번에 설치하는 묶음입니다. 마켓플레이스는 플러그인을 내려받는 주소(여기서는 GitHub 저장소)입니다. MCP는 Claude가 바깥 서비스(법령 검색 등)를 쓰게 해 주는 연결 장치입니다. API 키는 그 서비스가 발급하는 이용 번호입니다.

1-2. 함께 쓰면 좋은 것 (선택)

무엇 설치 쓰는 곳
ARS 플러그인 (academic-research-skills) /plugin marketplace add Imbad0202/academic-research-skills 다음 /plugin install academic-research-skills@academic-research-skills 개요, 초안, 인용 검증, 다관점 심사, 심사평 대응 (/ars-* 명령 16개). 라이선스 CC BY-NC 4.0
Zotero zotero.org 서지 관리. zotero 스킬이 이 라이브러리를 읽습니다
korean-law MCP 3부 korean-law-search 항목 참고 법령·판례 인용
RISS API 키 riss.kr/apicenter (대학·비영리 기관에 발급) keris-academic-search의 RISS 검색
kordoc npm i -g kordoc read-hwp가 HWP를 읽을 때 씁니다
python3 맥은 xcode-select --install zotero·kci-journal-finder 스크립트 실행

1-3. 첫 30분

  1. 논문 파일을 모을 폴더(예: 문서 폴더 안의 논문)를 만들고 Claude Code를 그 폴더에서 엽니다. 데스크톱 앱에서는 새 세션을 만들 때 그 폴더를 고릅니다. 터미널에서는 그 폴더로 이동한 뒤 claude를 입력합니다(맥은 Finder에서 폴더를 우클릭해 "폴더에서 새로운 터미널 열기", 윈도우는 폴더 빈 곳을 우클릭해 "터미널에서 열기"). Claude는 열린 폴더 안의 파일을 읽고 씁니다. 그러니 늘 논문 폴더에서 여세요.
  2. /paper-start를 입력합니다. 세 가지가 차례로 진행됩니다.
    • 점검: 무엇이 준비됐고 무엇이 선택 사항인지 표로 보여 줍니다. ➖ 표시는 고장이 아니라, 그 기능을 쓸 때만 필요한 것입니다.
    • 설정: 논문 폴더, 논문 노트를 쌓을 위키 폴더, 전공 분야를 한 번 묻고 저장합니다. 이 설정은 paper-study, wiki-recall, weekly-review, zotero가 함께 씁니다.
    • 길 안내: 지금 상황을 한 문장으로 말하면 알맞은 스킬 하나와 입력 예시를 줍니다.
  3. 스킬을 부르는 방법은 세 가지입니다.
    • 말로: "논문이 안 써져요"라고 하면 관련 스킬이 알아서 발동합니다.
    • 슬래시로: /paper-study처럼 스킬 이름을 직접 부릅니다. 플러그인으로 설치했으면 /paper-toolkit:paper-study처럼 보일 수 있습니다. 같은 것입니다.
    • 파일과 함께: "이 폴더의 draft.md 읽고 심사해줘"처럼 파일을 지목합니다.

습관 하나. 세션을 마칠 때 "오늘 한 것 정리해서 연구일지.md에 추가해줘"라고 해 두세요. 다음 세션은 "연구일지 읽고 이어서 하자"로 시작하면 됩니다. weekly-review도 이 연구일지를 읽습니다.

2부. 상황별 따라 하기

연구 흐름: 기획 → 수집 → 학습 → 집필 → 분석 → 퇴고 → 점검 → 투고처 → 심사 대응 → 제출

시나리오 1. 주제가 안 잡힐 때 — paper-writing-order

/paper-writing-order 논문을 시작해야 하는데 주제를 몇 달째 못 정하고 있어요. 관심 분야는 다문화 청소년의 인권교육이에요.

이 스킬은 처음부터 완벽한 주제를 내놓으라고 하지 않습니다. 대신 다섯 단계를 함께 밟습니다. ① 넓은 키워드를 정하고 ② 핵심 논문 2~3편을 발췌독하고 ③ 모은 인용문을 한계·모순·패턴으로 나눕니다. 연구 질문은 이 셋째 단계에서 드러납니다. 그다음 ④ 뼈대를 세우고 ⑤ 서론과 결론을 한 쌍으로 씁니다. 대화가 여러 번 오가므로 30분~1시간을 잡으세요.

초안이 이미 있다면 진단 모드로 부릅니다.

/paper-writing-order 진단 모드로. 제 서론 초안(intro-draft.md)이 왜 막히는지 봐줘.

시나리오 2. 선행연구 수집 주간 — ref-toolkit → keris-academic-search → Zotero → zotero

  1. 도구 고르기

    /ref-toolkit 체계적 문헌고찰은 아니고, 국내 문헌 위주로 빠르게 훑고 싶어. 어떤 도구 순서로 할까?

    Consensus·Elicit·Scite·RISS·KCI 같은 20여 개 도구 가운데 지금 상황에 맞는 순서를 골라 줍니다. 원칙은 두 가지입니다. 모든 문헌은 Zotero 한 곳에 모으고, 유료 도구는 마지막에 씁니다.

  2. 국내 문헌 훑기

    다문화 청소년 인권교육 관련 최근 5년 국내 박사학위논문과 KCI 논문을 검색해서 제목·저자·연도·학교(학술지)를 표로 만들어줘. 내 주제와 겹치는 정도도 상·중·하로 표시해줘.

    keris-academic-search가 RISS를 검색합니다. RISS API 키가 없으면 Claude가 웹 검색으로 대신 찾습니다. 겹침이 '상'인 논문은 주제를 차별화하려면 꼭 읽어야 합니다.

  3. Zotero에 담기 (직접, 한 편에 5초): 브라우저에서 Zotero Connector 버튼을 누르고 컬렉션(예: "2장 이론적배경")으로 분류합니다.

  4. 주간 점검

    /zotero 이번 주에 모은 문헌 중 인용 가능한 게 몇 편이고, 저자나 연도가 빠진 항목이 뭔지 알려줘.

    "전체 N건 중 인용 가능 M건"과 결손 목록이 나옵니다. 결손 항목은 대부분 Zotero에서 우클릭 → "PDF 메타데이터 가져오기"로 채워집니다.

체계적 문헌고찰(PRISMA)이 목적이라면 이렇게 자유롭게 검색하지 말고 /ars-lit-review로 검색식과 포함·배제 기준부터 세우세요. 검색 과정을 재현할 수 있어야 심사를 통과합니다.

시나리오 3. 논문 한 편 제대로 공부하기 — paper-study

/paper-study 이 논문 같이 공부하자: Banks-2021-multicultural.pdf

이번에는 Claude가 질문합니다. "이 연구가 반박하는 기존 관점은 무엇인가요?" 같은 질문에 답하고, 마지막에 논문 내용을 내 말로 세 문장에 담아 다시 설명합니다. 그러면 그 재설명과 문답, '내 논문에 적용할 아이디어'를 담은 노트가 /paper-start에서 정한 위키 폴더의 papers/에 저장되고, 관련 개념 노트와 [[링크]]로 이어집니다.

뼈대가 되는 핵심 논문 20~40편은 paper-study로 정독하고, 나머지는 /ars-3w로 왜·어떻게·무엇만 훑으세요. 모든 논문을 정독하려 들면 박사과정이 길어집니다.

시나리오 4. 장(章) 초안 쓰기 — wiki-recall → /ars-outline → /ars-full

  1. 쌓아 둔 지식 꺼내기

    /wiki-recall 2장 이론적 배경을 시작하려고 해. '다문화주의', '인권교육', '비판적 교육학' 관련해서 내가 정리해 둔 노트를 모아서 요약해줘.

    위키 폴더와 메모 폴더에서 관련 노트를 찾아 "가진 것"과 "빈 곳"으로 나눠 보여 줍니다.

  2. 개요 짜기

    /ars-outline 2장 이론적 배경. 구조는 ①다문화교육 이론의 전개 ②인권교육 접근 ③두 흐름의 통합 논의. 각 절의 근거 문헌은 위 노트에서.

  3. 초안 쓰기

    /ars-full 이 개요대로 초안을 쓰되, 각 단계마다 멈추고 내 확인을 받아줘. 인용은 [@citekey] 형식으로.

윤리 경계. 초안은 내 개요를 문장으로 옮긴 것일 뿐입니다. 반드시 내 문장으로 고쳐 쓰고, 인용은 모두 원문을 직접 확인하세요.

시나리오 5. 설문 데이터 분석 — tools/KBG-PAPER-A.html

브라우저에서 tools/KBG-PAPER-A.html을 엽니다. 데이터는 내 컴퓨터 밖으로 나가지 않습니다. 먼저 예제 데이터로 화면에 익숙해진 뒤, 내 설문 CSV를 붙여 넣습니다. 문항 접두사(SE1~SE5 등)를 보고 잠재변수가 자동으로 묶입니다. 경로를 그리고 부트스트랩을 실행하면 신뢰도·타당도·경로계수·매개·조절 표가 나옵니다. 판정 기준이 헷갈리면 tools/KBG-PAPER-A-manual.html의 치트시트를 보세요. 일반 통계는 Claude에게 바로 맡겨도 됩니다.

survey.csv 읽고 기술통계, 신뢰도(Cronbach α), 성별 t검정 돌려서 APA 표로 만들어줘. 사용한 코드도 보여줘.

시나리오 6. 퇴고 — humanize → toego-korean → korean-spell-check → korean-character-count

큰 것부터 작은 것 순서로 고칩니다.

  1. AI 티 걷어 내기: /humanize 2장-초안.md — 내용은 그대로 두고 문체만. strict로. 번역투, 기계적 병렬, 피동 남용을 걷어 낸 원고와 함께, 무엇을 왜 바꿨는지 목록이 나옵니다. 결과가 아쉬우면 /humanize-redo로 한 번 더 다듬습니다.
  2. 사람 손 퇴고: 내 문장으로 고쳐 쓴 다음 /toego-korean으로 구조 → 문단 → 문장 순서로 점검합니다.
  3. 맞춤법: /korean-spell-check 2장-수정.md — 바뀐 곳만 보여줘
  4. 분량 규정: /korean-character-count 초록.md — 공백 포함/제외 글자수. 학교 규정은 국문 800자 이내야.

시나리오 7. 투고·심사 전 최종 점검 — 세 겹의 방어선

  1. 형식: 보고 가이드라인을 고르고 원고를 점검합니다.

    /reporting-guideline-router 내 연구는 혼합방법(설문 + 심층면접)이야. 어떤 가이드라인으로 점검해야 해? 그 체크리스트로 full-draft.md 점검해줘.

  2. 인용: /ars-citation-check full-draft.md 본문 인용과 참고문헌 목록을 맞대어 보고, 연도 불일치와 깨진 DOI를 찾아냅니다. 법령이나 판례를 인용했다면 korean-law-search에 "이 원고의 법 인용 검증해줘"라고 맡깁니다.

  3. 내용: 모의 심사를 받습니다.

    /paper-critical-review full-draft.md — Reviewer 2 관점에서 사정없이. 방법론과 선행연구 방어선을 공격해줘.

    이 심사는 세 가지를 더 봅니다. 문장마다 결과에서 나온 사실(FACT)인지 저자의 해석(SYNTHESIS)인지 가르고, 6항목 구조 감사(고아 숫자, 초록·서론·결론의 정렬 등)를 하고, '주장 도전 원장'을 작성합니다. 핵심 주장에 풀리지 않은 반론이 남아 있으면 판정은 Major Revision 이하로 나옵니다.

시나리오 8. 어느 학술지에 낼까 — kci-journal-finder

사회복지학 분야 KCI 등재지 중에 연 4회 이상 나오고, 대학원생 심사료나 게재료 감면이 있는 곳 추려줘.

규정은 바뀝니다. 투고 전에 학회 홈페이지에서 한 번 더 확인하세요.

  • 부르기: "어디에 투고하지", "교육학 등재지 추천", "게재료 무료 학술지"

Claude가 만든 인용을 믿어도 되나요 아니요. 인용은 모두 원문을 직접 확인해야 합니다. 인용 검사 도구는 형식과 존재 여부만 볼 뿐, 내가 원문을 읽었다는 확인을 대신하지 못합니다.
AI를 썼다고 논문에 밝혀야 하나요 대학원과 학술지 규정을 따르세요. 도구를 쓴 내역(검색, 교정, 형식 점검)을 연구일지에 남겨 두면 어떤 규정에도 대응할 수 있습니다. /ars-disclosure가 공개문 초안을 도와줍니다.
긴 문서를 주면 중간에 끊겨요 "2장만", "3.2절만"처럼 범위를 좁혀 장 단위로 작업하세요. 품질도 그편이 낫습니다.
zotero 스킬이 서재를 못 찾아요 /paper-start에서 데이터 폴더 위치를 설정하세요. Zotero → 설정 → 고급 → 파일 및 폴더에서 확인할 수 있습니다.
kci-journal-finder가 "다운로드 실패"를 띄워요 첫 실행에는 인터넷이 필요합니다. 한 번 받은 뒤에는 오프라인에서도 저장본으로 작동합니다.
비용이 걱정돼요 코칭, 검색, 퇴고 같은 일상 작업은 가볍습니다. 무거운 것은 /ars-full(1회에 약 $4~6)과 /ars-reviewer이니 꼭 필요할 때만 쓰세요.
